# 潜行影响与输入扩展评估

日期：2026-09-15。当前版本 0.8.0。潜行隐藏、键盘组合键已经用户测试通过；手柄支持已通过用户游戏测试，包括断开重连。

## 潜行侦测待办

本插件使用原生 NiPointLight / ShadowSceneNode，未排除潜行亮度查询。已核对的 CS 逆平方实现处理 BSLight_GetLuminance，因此不能宣称面光仅影响画面或不会影响潜行。用户已通过游戏测试确认：面光确实会影响潜行侦测。尚未量化影响程度，也未逐一验证所有光照模式。

已实现并默认启用：提供“潜行时自动关闭玩家面光”，进入潜行暂时隐藏、退出后按启用状态恢复，不修改用户持久化 Enabled 值。此项不是彻底的侦测隔离，对话灯照到玩家仍可能影响。完全不参与侦测需要专项研究亮度查询路径与 CS 钩子兼容性。

## 键盘修饰键

可在现有输入事件监听器上扩展。键盘主键保持现有配置，新修饰键默认无，保持 L 单键兼容。第一版提供无、Shift、Ctrl、Alt，左右同类键均接受；先按住修饰键再按主键触发一次，主键长按不重复。设置修饰键后，单独主键不触发。建议按精确修饰键组合匹配，避免额外修饰键意外命中。暂不混用键盘与手柄作为一个组合。

不要在排除菜单输入前停止所有状态更新，否则释放修饰键可能漏记。优先核对设备当前状态，或完整维护按下/释放状态并在失焦、打开菜单、读档时清理。执行任务前继续检查运行条件，但不要重新依赖可能已释放的修饰键。

## 手柄

现有代码已接收键盘和手柄事件，手柄默认禁用。CommonLib/SKSE 提供游戏手柄事件与 GamepadMaskToKeycode / GamepadKeycodeToMask，可复用输入监听器，不需要新增运行库。

建议与键盘分别配置，默认禁用手柄绑定，避免占用已有操作。支持主键和可选手柄修饰键，例如 LB + D-pad Up；这是组合示例，不承诺在每个整合中无冲突。不能把手柄原始位掩码直接按键盘扫描码保存。第一轮覆盖标准手柄按钮，LT/RT 已开放，使用引擎按下/释放事件，需要实测，防止模拟值波动连续触发。

继续不吞掉游戏输入。组合键并不会取消其原有动作，用户应选择不冲突的绑定。只保证游戏输入层提供标准事件的控制器；Steam Input 映射为键盘时走键盘配置，其他映射需实测，不能承诺所有硬件原生支持。

## 建议界面与兼容

玩家面光页将快捷键区域分为键盘（主键 + 修饰键）和手柄（禁用/主键 + 修饰键）。沿用当前即时预览与统一保存，但配置菜单内不执行面光切换。保留自定义键显示，禁止主键等于修饰键。按键命中统一汇入一次切换请求，避免同一输入批次重复开关。

## 验证

键盘无修饰兼容、左右修饰键、主键/修饰键先后顺序、长按、菜单中释放、Alt-Tab、读档；手柄单键/组合键、同批次按下、断连重连、键鼠切换、Steam Input 映射。同步确认不会重复切换或误保存状态。
