# 低光照自动面光：初步评估

日期：2026-09-17。本轮仅评估，未实现自动亮度控制。

结论：基础阈值检测原型难度中等；准确排除自身补光并兼容 CS/Jiaye/ENB 观感的成品难度中高。

本地 CommonLib 的 HighProcessData 存在 lightLevel，游戏也有 GetLightLevel 条件/Actor 接口。这是可以研究的角色受光指标，不应直接当成纯环境光或后处理后的屏幕亮度。需要确认运行时访问、刷新频率、无有效样本时的行为。

主要难点：

- 自身补光反馈：现有面光已被用户证实影响潜行侦测，需实测它对读取值的贡献。若开灯后数值变亮，直接以同一阈值控制会导致反复开关。分离开关阈值与延时只能减少抖动，不能保证消除自身贡献。应先研究排除自身光源/查询路径，而不是定期可见地熄灯测量。单纯冻结开灯前样本也无法正确应对走进明亮区域。
- 游戏受光值与观感不等价：CS 的间接光、SSRT、曝光和后处理可能影响画面，但不一定反映在该值中。仅天气、时间或室内标志不足以表示火把旁与墙角的差异。
- 状态优先级：自动亮度只决定当前是否发光，不频繁写 Enabled；手动禁用、潜行隐藏、第一人称隐藏应优先。对话自动开关与自动亮度需要明确结合方式。
- 稳定性：低频采样、开灯/关灯两个阈值、持续时间确认及过渡；读档后丢弃旧样本，未知数据不可当成黑暗。

建议下一步先做只记录数值的诊断原型，分别比较自身灯开关、室内外、阴影与火把旁，以及 Jiaye 0516/0816。确认数据有效且能处理反馈后，再实现可选自动模式及阈值。不能在未验证前承诺各种渲染环境都准确。
