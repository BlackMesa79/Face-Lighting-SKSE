# 面光优先保护测试版（2026-09-26）

## 2026-09-27 修正（当前本地测试构建）

下面的 09-26 行为记录属于历史方案。按最新要求，当前取消玩家周围空间避让，非对话时玩家与最多四个次要 NPC 光源允许共存；随从优先于指定 NPC，满载抢占保留。对话菜单打开时，暂停除玩家和当前对话对象之外的所有面光，关闭菜单后按既有开关及预算恢复；即使说话者暂时缺失，也不会提前恢复其他光源。预算在无效角色过滤后分配，淡出对象也占预算；新对话对象替换旧对象时，旧对话仅在没有其他来源时释放。未更改用户配置，未重新制作或覆盖已发布的 0.9.1 压缩包。

渲染检测研究：本地 CommonLib 的 BSRenderPass 暴露 geometry、numLights、sceneLights，可研究在原版光照提交阶段记录目标头部网格是否选入本模组的 BSLight。ShadowSceneNode 的场景列表只能反映注册/队列状态，不能证明最终显示。未选入也不等于超限，应区分没有渲染目标、视野裁剪、距离和材质等原因，并跨多帧观察。CS 的聚簇光照使用额外的 GPU 列表，不能仅凭原版通道列表判断。当前未安装新渲染 hook；后续应先做只读诊断、校验各运行时布局和线程时序，不直接接入自动关灯。

本次是 0.9.0 基础上的本地测试构建，未重新制作发布压缩包。

## 行为

- 玩家光源独立管理。对话请求存在时，其他 NPC 光源立即释放，旧对话对象也让位。
- 非对话期间最多保留 4 个次要光源，指定 NPC 优先于随从；这是插件自己的保守预算，不是引擎的光源上限。
- 玩家面光实际存在时，按两者光照范围、配置偏移和 256 游戏单位的安全余量，暂停附近次要面光。恢复额外要求 64 单位距离，减少边界抖动。CS 反平方模式使用实际计算范围。
- 暂停不修改名单、个人开关或存档。用户关闭、潜行、死亡、第一人称设置继续生效。允许恢复的角色重新渐亮，安全释放立即执行。
- 不增加 INI 项。现有 INI 和存档无需迁移。

## Review

- 修复容量满时只能清退淡出对象、无法抢占活跃低优先级对象的问题。
- 预算包含淡出对象；保护释放在本帧 NPC 渲染更新前完成，避免保留淡出光源继续争抢。
- 同一角色多个来源仍复用一盏灯，对话覆盖指定 NPC 和随从设置。
- 光源日志增加角色 ID 与清理原因；开启 DebugLogging 后可区分保护释放和场景/骨骼无效等情况。
- 检查玩家更新、NPC 管理、随从扫描与偏好、指定名单、光源生命周期和死亡/潜行判定；未在本次静态检查中确认其他导致用户所述失效的根因。

## 限制与测试重点

本方案主动降低本模组灯光之间的竞争，不改变引擎光源选择，也无法保证外部模组和场景光源参与时一定可见。空间保护使用角色位置与保守余量估计，不是逐网格精确相交。预算内同优先级沿用提交顺序，不实现最近者调度。

请在多随从场景测试：玩家开关灯、靠近/远离随从、连续更换对话对象、潜行/起身、第一/第三人称、读档及室内外切换。附近随从因玩家保护而熄灯属于预期；对话期间其他 NPC 熄灯也属于预期。

自动测试覆盖原有生命周期、来源切换、容量、淡入淡出，以及新增的活跃对象抢占、对话独占、预算限制、空间否决后恢复和来源重叠。
