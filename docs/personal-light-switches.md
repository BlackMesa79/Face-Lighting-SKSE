# 个人面光开关统一（本地测试构建）

日期：2026-10-07。构建标识 `0.9.5-personal-light-test.1`，资源版本 0.9.5.0。包含此前的配置保存路径修复。公开 0.9.5 ZIP 未重新打包。

2026-10-08：用户本地游戏测试通过，纳入 0.9.6 正式安装包；原 0.9.5 产物保留。反馈用户的场景仍待确认，不能把本地验收视为其问题已全部解决。

## 行为

- 指定 NPC 和随从菜单的个人开关同步更新该角色的已有指定记录及随从禁用偏好。关闭后另一常驻来源不会继续点亮；开启随从不会额外创建指定记录。
- 快捷键检查随从、指定两组是否开启及其个人偏好，只要其中一个有效来源开启，就同时关闭两种偏好；否则开启。普通 NPC 首次开启添加指定记录，已识别队友复用随从偏好。未识别的独立随从继续作为普通 NPC 处理。
- 快捷键开启时自动保存并启用对应总开关：队友用随从组，普通 NPC 用指定组。关闭不会改变总开关。菜单个人开关允许在组关闭或预览时编辑偏好；来源组仍各自独立。
- 菜单显式添加目标仍将队友加入指定名单，同时同步随从偏好。“移除”只删除指定记录，不代表禁止自动随从面光。
- 对话面光独立：个人开关关闭后，当前对话对象仍可使用对话灯，结束后不会恢复被关闭的个人灯。个人操作不修改对话或玩家设置。
- 个人偏好随游戏存档 / SKSE co-save 保存；参数保存按钮不代替保存游戏。旧存档不主动迁移，下一次个人开关操作会统一该角色的两种偏好。

## 保护与验证

所有菜单任务复用指定名单的存档会话检查，锁顺序保持指定名单 → 随从偏好。名单和禁用偏好先分配暂存；快捷键需要保存总开关时，写入失败不发布任何个人偏好，容量不足时不写配置。API V1 布局和调用约束不变。

构建及 16 项测试通过。新增回归覆盖旧存档两种来源开关不一致、仍在队伍中关闭后完成淡出释放、独立对话灯结束后不恢复个人灯、总开关关闭、满额名单、偏好容量及保存失败的回滚。真实 SKSE 菜单任务和游戏渲染效果仍需游戏测试。

建议实测同一随从同时在两种名单内：分别在两个页面关灯，确认仍在队伍时熄灭；准星快捷键反复切换；关灯后对话及结束；解雇再招募；保存游戏、重启并读档。也检查两个总开关均关闭时快捷键只启用对应组，以及普通 NPC 的首次添加行为。

此修改解决可确认的来源交互不一致，尚未证明受影响用户没有其他渲染残留或外部模组光源问题。
