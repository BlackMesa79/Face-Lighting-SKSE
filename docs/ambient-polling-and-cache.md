# 环境判断频率与静止时的缓存刷新

日期：2026-10-04。实现与结论以当前本地开发构建为准。

通用页“环境检测频率”下拉框提供三档：性能优先每 1 秒（默认）、均衡每 0.5 秒、响应优先每 0.2 秒。两个自动来源共用调度，配置 General/AmbientPollMode=0/1/2。不增加公开 API 字段或改变 V1 布局；配置指纹覆盖该选项。

每帧继续处理暂停、换目标/cell/配置、资格、安全清理和动画，读取 raw/过滤样本及阈值计时只在调度到期时执行。持续时间使用实际时间，较长断档重新建立持续条件。相邻正常轮询不被当作暂停；切换频率立即重新调度，无累积回补。瞬时亮度波动可能落在两次轮询之间而不被观测，这是降低频率的预期取舍。

实时排除 hook 不新增世界查询，只跟随原有引擎光照计算。档位降低并不节流引擎 hook 的每次逐灯查表/累计，也不能据此声称整体开销降低到原来的固定比例。灯光数量和场景渲染开销继续独立。

## 静止反馈的当前证据

1. FaceLight/LightProbe/DialogueAmbientPolicy 未比较玩家位置来决定是否判定；有新读数时原地也能改变开关，纯逻辑回归覆盖这一点。
2. 固定补偿读 HighProcessData.lightLevel；实时排除仅在引擎整体查询与 SetLightLevel 配对完成时更新。没有主动请求刷新。
3. 已捕获的 1.6.1170 CalculateLightValue 函数入口先读 AIProcess+8（middleHigh），随后检查 +0x328 的标志及时间等分支，能跳过重算。该未知字段不是 high 的 voiceTimer，也未在当前代码写入；从这些字节不能推断所有情况下移动必定/仅仅才会刷新。
4. 当引擎不产生新数据时，缓存读取频率不是决定因素；实时排除样本在同 cell 下也只保留一秒有效期，过期意味着暂停新决定，不是黑暗。不能放宽有效期来把陈旧值伪装成新采样。
5. 现有本机最近日志未启用有效的该场景诊断，无法仅凭日志确认反馈根因或宣称修复。该构建只完成频率控制。

## 后续验证

站定后外部火把/环境变化，分别观察 raw 和配对过滤值是否刷新，再少量移动比较。LightDiagnostics=1 的日志包含 pollSeconds/sourceRefresh；实时排除另用 ExclusionDiagnostics=1（保存并重启安装 hook）。比较 paired/rejected、过滤值、ageMs、阈值、暂停/过渡稳定状态，区分未采样与已有样本未满足条件。诊断完成后恢复原配置，不默认开启大量日志。

若证实引擎静止条件跳过重算，再单独研究安全的主动查询或官方缓存失效路径；仍须核对 ABI、与 Community Shaders 的调用链、副作用及 SE/AE 布局。不要直接改未知 +0x328、重入完整 AIProcess 更新或写原始潜行缓存。
