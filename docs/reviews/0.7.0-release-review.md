# FaceLighting 0.7.0 发布前审查

日期：2026-09-14。范围：本项目 src/include、构建配置、现有测试、0.7.0 发布压缩包，并对照本地 Jiaye CS 着色器。此次不修改代码或替换发布包。

## 发现

### P2：色温线性转换没有检查 CS 全局 Linear Lighting 状态

src/FaceLight.cpp:115-116 用 CS 版本识别结果与本插件的 csInverseSquare/csLinear 标记决定是否预先线性化颜色。CS 的 Common/Color.hlsli:239-259 则明确在 ENABLE_LL 关闭时直接使用输入颜色，忽略该线性标记的转换含义。

复现条件：CS 被识别，全局 Linear Lighting 关闭，面光设置 3200 K，普通衰减下切换本插件线性开关。插件输出的绿色分量从约 0.7226 变成 0.4808，着色器此时直接使用该值，造成非预期的色温/亮度变化。默认 6500 K 两条路径都是白色，因此默认配置测试不会发现。默认开启逆平方的对话面光也受这个条件影响。

建议：把实际全局线性状态纳入颜色空间选择；若实验分支没有可靠接口，则提供明确的颜色空间选择或兼容回退，不能把“检测到 CS”当成“全局 Linear Lighting 已开启”。增加全局开/关 × 本插件线性开/关 × 非白色的组合验证。

### P2：INI 自定义快捷键会在菜单中错误显示为 Off

src/Settings.cpp:39 允许 0–255 的扫描码，Hotkeys.cpp 按原值监听；src/ConfigMenu.cpp:55-58 只查找 Off 和 A–Z，找不到时 keyIndex 保持 0。

复现条件：设置 PlayerHotkey=59（F1 扫描码）后加载。菜单显示 Off，但运行时仍接受 59。用户无法从页面判断真实配置；选择当前 Off 项也可能不会触发 ImGui Combo 的值变更，因此不能可靠禁用。

建议：保留自定义值并显示明确的 Custom/扫描码项，或在加载和运行时统一限制为菜单支持的键。增加自定义扫描码的显示与禁用检查。
