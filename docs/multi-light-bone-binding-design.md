# 多光源与骨骼绑定实现设计

研究日期：2026-10-01。接续收藏轮盘接口设计；此功能尚未实现，单向光源实验和引擎光源丢弃检测也尚未实现。

## 当前结构与可复用部分

`LightInstance` 固定查找 `NPC Head [Head]`，绑定一盏 NiPointLight，负责场景注册、骨骼/模型变化清理、颜色范围和过渡。
`NpcLightManager` 为每个角色挑选一个最高优先级来源，再更新一盏灯。玩家灯独立管理。
`LightPlacement` 已处理骨骼旋转和去除缩放，使偏移保持游戏单位。

因此多灯主要是结构扩展，不需要先实现聚光灯，也不需要改角色自动发现逻辑。

## 最小数据模型

将灯的配置与角色控制分离：

| 数据 | 字段与用途 |
| --- | --- |
| LightSpec | 预设内稳定灯 ID、名称、enabled、boneName、偏移、旋转跟随方式、色温或颜色、强度、范围、过渡 |
| LightPreset | 稳定预设 ID、名称、LightSpec 列表和版本 |
| ActorLightGroup | 角色句柄、当前来源/预设、用户总开关、每个灯的运行实例 |
| LightRuntime | 骨骼/root/scene 引用、NiLight/BSLight、应用参数和淡入淡出状态；不序列化引擎指针 |

角色层保留对话 > 随从 > 指定的来源规则，选好一个预设后渲染它的灯组，不把不同来源的灯组叠加。旧配置迁移成一个固定 ID 的头部主灯，原有视觉效果保持可复测。

LightInstance::Update 接收已选择的骨骼/灯参数，不再依赖巨大 Settings::Values 的整对象比较；只有灯参数变化才更新照明数据。新增骨骼名变化也需要重新绑定。先完成模型边界，再考虑减少比较的优化。

## 任意骨骼的边界

配置菜单遍历当前角色实际加载的 NiNode，提供骨骼下拉选择和搜索。不能把任意几何对象都当骨骼。

- 人类、兽类、自定义骨架、变身与第一人称模型不保证具有相同节点。
- 同名节点可能不唯一，首版只允许唯一匹配，否则要求重新选择；未来可增加父节点路径定位。
- 灯实例自身及本模组容器节点不得进入选择列表，避免灯绑定灯或形成父子循环。
- 查找失败显示“骨骼不存在”，暂停该灯，不静默绑定其他节点。
- 换装导致模型重建、读档、场景切换时检测 root/节点变化并清理重绑；旧节点强引用不等于仍属于活跃模型。
- 默认在 3D 重建或选择变化时解析骨骼，而不是每盏灯每帧递归扫描；动画帧只用缓存的当前有效节点变换。
- 骨骼 scale、位置与数值继续校验。骨骼局部偏移跟随动画；世界/角色轴偏移与绑定位置分开表达。

第一人称现有灯绑定 cameraRoot。首版可继续将其作为独立的相机灯，并将骨骼自定义限定第三人称，避免声称第一人称也能绑定不存在的腿/头节点。

## 光源预算必须改为灯数

当前四个次要条目约等于四盏灯；多灯之后四个角色每人三盏就会变成十二盏。不能沿用角色条目数作为渲染预算。

保留角色层优先级，另引入每灯排序：玩家主灯、当前对话主灯、其余受保护的辅助灯、随从主灯、指定主灯、普通辅助灯。具体预算值须实测决定，不把“保留”解释为引擎最终照亮保证。

需要区分配置数量、申请数量、场景已注册数量；过渡中的灯也计入实际预算。争抢时先让出辅助灯，角色主灯优先，避免某人的辅助灯占满预算使其他角色完全无灯。

对话时临时释放其他 NPC 的整个灯组；结束后按用户状态/预算恢复。潜行/死亡/缺失模型释放整组，缺失某个骨骼仅暂停对应灯。所有权和 Clear/Unregister 必须幂等。

## 环境光与持久化

- 每盏灯都要进入 LightExclusionProbe 登记，玩家灯标记为 player，NPC 灯标记为 npc，清理逐盏注销。
- 固定补偿模式无法自动准确排除不同位置/强度的多灯。增加灯位后需提示重新校准，不能简单地把原补偿乘灯数。
- 实时排除方案仍只允许已经验证的 1.6.1170 布局，多灯支持不扩大该运行时范围。
- 将预设保存为带 schemaVersion 的 JSON，使用结构化解析器、有限灯数、数值校验和临时文件替换；复用工程工具链中可用解析库，实施时核对许可证。
- 默认值继续内置；安装包不附带用户初始 FaceLighting.ini。自定义预设不被升级覆盖。
- 角色与预设的关联用 SKSE co-save 记录并 ResolveFormID；骨骼名和偏移属于预设，不序列化节点地址。保存游戏与保存预设两种操作明确区分。

## 编辑流程

先仅为玩家开放，建议最多三盏配置灯：新增/删除、骨骼选择、位置输入、色温/颜色、强度/范围和开关；主灯可重置，预设支持复制与保存。

继续沿用菜单预览、保存、取消：取消时恢复整个灯组而非只恢复一盏。编辑预览可临时放宽环境抑制以看清效果，但必须有明确模式及退出恢复，不绕过死亡和无效节点保护。

交互需要实时预览，首版无需实现鼠标 3D 拖拽。聚光灯朝向参数待单向照射验证后加入，旋转点光源不会产生单向照射。

## 推荐拆分

1. 先完成轮盘 V1，以角色整组开关语义对接。
2. 引入灯组/预设模型，旧头部单灯作为回归基准，现有 NPC 行为保持一致。
3. 玩家第三人称三灯和骨骼选择，验证保存/取消、读档、换装、死亡及缩放。
4. 验证所有灯的预算与环境光登记，再开放随从/指定预设。
5. 按实测结果决定相机灯、预设共享和聚光灯等扩展。

验证需包含 SE 1.5.97 / AE 1.6.1170 的对象布局、原版 / CS 渲染、缺失及重名骨骼、不同骨架、预设损坏、组关闭和过渡中卸载。自动测试验证策略及配置边界，实际绑灯效果仍需游戏截图和存档场景实测。
