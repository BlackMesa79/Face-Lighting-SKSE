## 已检查

- ABI：原 `FaceLightingAPI.h` 无改动；V1 独立原表、V2 新表，固定宽度数据、默认 size、保留字段、完整参数范围和线程边界。实际 DLL 测试验证版本 1/2、未知版本、V2 的 v1 指针、短输出与未建立游戏线程的拒绝。
- 原子性：完整快照暂存，任何参数、重复目标或角色验证失败均不换目标/暂停状态、不续租；调用方内存不保留。输出仅在成功后发布。输入缓冲区由可信 SKSE 客户端负责有效性，C++ 异常边界不承诺捕获无效指针的 SEH。
- 生命周期：一个外部租约、单调 ID 不复用、存档代次检查、超时与暂停计时、每帧安全目标清理、读档/加载清理、显式结束/空快照释放。逻辑超时可在 API 查询中发生，场景兜底在游戏主线程更新恢复后执行；不承诺冻结游戏时后台渲染清理。
- 去重/优先级：原管理器按角色复用一盏灯；External 优先于 Dialogue/Follower/Selected，最多四个临时参与者；活动快照排他控制 NPC，玩家未列入则走自身原规则。无名单或配置写入。
- SE/AE：未增加 Actor 基类固定偏移、运行时专属补丁或新引擎槽位；沿用现有 ActorRuntime、GetActorRuntimeData、头骨/场景访问和 CS 渲染。实时环境排除继续保持 1.6.1170 边界。
- 接入文档与示例：明确 FormID 是引用而非 base ID、主线程调用、租期与保活、暂停恢复、End 的调用责任、失败处理、环境样本位置与有效性。示例纳入 PublicAPITests 构建，保证 C++ 编译通过，不代表真实 CCC 场景已执行。

## 审查过程中修正并覆盖的事项

1. 临时目标关灯时直接采用零强度/新颜色会中断或改变淡出。NPC 保留上一帧参数但使用本次过渡时间，玩家保留上一帧发光参数；无灯的禁用请求只做来源否决，不反复创建空灯。测试覆盖淡出后的实际管理条目释放和默认对话来源无法绕过。
2. 外部会话在 DialogueMenu 关闭前 End，原“对话结束自动关闭玩家灯”可能改写保存的开关。PlayerDialoguePolicy 记录本次对话由临时会话控制，吞掉其关闭边沿，下次普通对话恢复原策略；增加结束/读档回归。
3. 预览/暂停/超时若只删逻辑快照，旧 External 条目可能继续保留。独立 DropSource 释放临时 NPC 条目，玩家临时归属退出时清理并恢复原需求；禁用、空快照、超时、旧 token 不得结束新会话均有测试。
4. NPC 过渡此前使用未经限幅的 wall-time delta。更新限制为最大 0.1 秒，暂停时为零，与玩家过渡一致；安全清理不等待淡出。
