# NPC 面光进度

## 当前发布计划（2026-09-18 调整）

原计划在 1.0 一并实装指定 NPC 面光、随从面光、范围内 NPC 自动添加面光和全新配置菜单，现调整为分阶段发布：

- **0.9（当前开发目标）**：指定 NPC 面光、随从面光和全新配置菜单。指定 NPC 面光和新版菜单已实现，等待游戏内验证；随从面光尚待实现。
- **后续版本（版本号与日期待定）**：范围内 NPC 自动添加面光、Skyrim 1.7.x 支持及其他剩余内容延后，不作为 0.9 的发布条件。

此次仅调整发布范围；开发 DLL 版本仍暂为 0.8.2，已发布的 0.8.2 压缩包保持不变。下文保留各阶段记录，当前实现状态以末尾进度及使用验收说明为准。

## 早期阶段记录

0.5.0 已实现对话面光：独立配置、CS 适配、中英文菜单、可开关的淡入淡出。复用 LightInstance 管理光源，ActorHandle 跟踪对话目标。目标来自标准 Dialogue Menu / MenuTopicManager，最多持有当前与退出中的两个 NPC 光源，加载和卸载直接清理。详见 README 的 0.5.0 说明。

下一个独立模块为用户指定 NPC 的常驻面光。本轮不实现附近 NPC 自动补光，也不扫描人群。后续需明确指定/移除入口、名单持久化以及与对话面光同时命中同一 NPC 时的优先级，以免重复补光。

## 统一管理基础（0.8.2 后开发构建）

现有对话面光已迁移到 `NpcLightManager`，游戏内效果待回归测试。版本号暂不递增，正式 0.8.2 压缩包保持不变。

- `LightInstance` 独立负责场景光源创建、参数更新、骨骼位置和渲染器注销；玩家面光继续使用独立实例。
- 对话模块只选择目标并提交本帧请求。管理器按 ActorHandle 合并，同一 NPC 只持有一个实例；没有续交请求时淡出，重新请求时从当前亮度恢复。
- 内部暂定参数优先级：对话 > 指定 > 随从 > 附近。只实现对话请求生产者，其他来源仅预留标识，不提供用户入口或外部 API。高优先级来源退出后，仍有请求的 NPC 直接恢复其他来源参数，不额外创建或关闭灯；参数切换目前不插值。
- 当前容量仍为 2，包含淡出实例；新目标优先淘汰最早加入且已无请求的实例，不淘汰仍被请求的目标。容量不是全局优先级抢占机制。接入多人常驻模块时需另行确定容量、公平性和距离筛选规则。
- 每次更新验证 ActorHandle、第三人称 3D 与 attached cell；失效直接注销。LightInstance 保持对模型、头骨、场景和 cell 变化的检查。加载、新游戏、返回主菜单清空所有实例和本帧请求。
- 对话参数预览仍同步到淡出中的对话实例；所有场景操作限定在原有主线程更新路径。持有状态沿用进程期存活设计，避免退出时在引擎分配器销毁后释放场景资源。
- 不新增 INI，不持久化 ActorHandle，不增加人群扫描，不改变玩家对话自动开关或 CommonLib 依赖。

自动测试覆盖：同 NPC 多来源去重、重复提交更新、优先级回退、淡出反转、快速切换容量、无效目标清理、关闭过渡、完整重置和零容量。已有设置、位置、CS、本地化、玩家对话策略测试同时通过。

游戏回归：普通对话开始/结束；快速更换对话 NPC；淡出中重新对话；过渡开关与参数预览；对话中读档、加载和场景切换；确认无残留、叠加或玩家面光回归。
