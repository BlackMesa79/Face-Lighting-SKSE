# 对话玩家面光与 CCC 对接评估

日期：2026-09-16。当前开发构建保持 0.8.1；此前正式包不替换。两个开关已编译、部署并通过自动化检查，待游戏验收。API 仅评估，没有导出接口或修改 CCC。

## 本次实现

玩家面光页提供两个独立选项：进入对话自动开启默认开启，结束自动关闭默认关闭，保存后从下一次相应对话边沿生效。已有 INI 明确保存的值继续保留：

- EnablePlayerOnDialogue：对话开始时，原本关闭则开启并保存 Enabled=1；原本开启不变。
- DisablePlayerAfterDialogue：对话结束时，无论原先是手动还是自动开启，都关闭并保存 Enabled=0。这一语义已由用户明确确认。

| 进入自动开 | 结束自动关 | 行为 |
| --- | --- | --- |
| 关 | 关 | 沿用手动开关 |
| 开 | 关 | 开始时开启，结束后保留当时状态 |
| 关 | 开 | 开始不改变，结束统一关闭 |
| 开 | 开 | 开始时开启，结束统一关闭 |

只在 DialogueMenu 的开/关状态发生变化时执行，不持续强制开灯；对话中可以手动关闭。第一人称和潜行隐藏继续优先控制实际可见性，强度为 0 仍不发光。NPC 面光开关不影响这两个玩家选项。

自动切换只写 Enabled，不覆盖其他配置或预览；写入失败保持旧状态并记录日志，不逐帧重试。设置页面同步 Enabled，避免旧草稿在保存时复活旧状态。读档/返回主菜单清理对话边沿状态，不把清理当成一次正常对话结束。

该功能依赖标准 DialogueMenu 生命周期。菜单被其他模组临时关闭时也视为结束；纯取景镜头切换不触发。CCC 完整会话支持应使用下面的显式 API，不能将本次小功能视为已完成 CCC 兼容适配。

自动化验证：开关组合及初始状态、持续对话不重复触发、手动关闭不被反复打开、重置、持久化、预览保留、保存失败，及现有光照/位置/本地化回归。

游戏验收：四种选项组合；对话前手动开启后退出；对话中快捷键；第一/第三人称；潜行；交易后返回对话；对话中读档；保存、退出与重新进入游戏。

## CCC 可行性

结论：可行。基础的按会话请求玩家与指定 NPC 补光为中等工作量，已有光源实现可复用；按镜头布光、镜头过渡、暂停恢复和其他面光来源去重则需要更完整的管理层。

公开说明确认 CCC 控制玩家/NPC 正反打、镜头位置及发言者切换；交易等菜单可暂停后恢复镜头。其公开源码仓库为 fatalCMD/ccc。仓库说明与 Nexus 发布页版本不同；本次访问源码文件失败，未逐行验证当前实际 DLL 的内部状态或现有对外接口。以下为建议协议，而不是已存在的 CCC API。

## 建议第一阶段协议

Face Lighting SKSE 导出带版本号的函数表查询入口（例如 RequestPluginAPI）。CCC 在插件加载完成后可选获取，未安装或版本不匹配时正常退回无打光，不形成硬依赖。边界使用固定宽度字段和带 size/version 的结构，避免跨 DLL 传递 STL 容器。

最小能力：

1. BeginSession：取得本次镜头会话的请求 token。
2. SetActorLight：指定玩家/目标 NPC；传入启用状态、可选参数覆盖。至少明确坐标空间：角色朝向、骨骼局部；相机空间可作为后续能力。
3. SetSessionActive：暂停与恢复，例如交易界面、CCC 暂时释放镜头。
4. EndSession：撤销该会话请求，恢复 Face Lighting SKSE 自己的设置和光源需求。

镜头切换时 CCC 可改变目标或权重；第一版可先维持玩家与对话对象同时补光，降低频繁切灯和镜头过渡的协调成本。

## 必须处理的边界

- Face Lighting SKSE 持有光源，CCC 只持有请求 token；不要直接暴露 NiPointLight 指针。
- 对象标识必须可验证，内部转换为 ActorHandle，卸载/死亡/读档后失效清理；不要长期保存裸 Actor 指针。
- 请求复制后交由主线程执行；API 返回请求接收状态，不将异步接收等同于已创建光源。
- 同一个 Actor 的默认对话面光与外部请求合并为一盏灯，明确临时覆盖优先级，避免叠加过曝。
- 外部请求不写用户 INI；按会话恢复，不简单地在镜头结束时把所有灯一律关闭。
- 读档、返回主菜单、CCC 禁用、会话结束和异常中断都能撤销请求；设计超时/保活机制处理遗漏释放。
- 明确第一人称、第三人称模型可见性、潜行隐藏是否允许被外部镜头请求覆盖。当前自动开关不会绕过这些规则。
- 相机相对打光需 CCC 提供相机基向量/位置或最终世界位置，并明确更新时机，避免相机钩子与光照钩子先后造成一帧延迟。

与作者进一步确认：只需按会话开关双方面光，还是要按当前取景目标切换灯；是否需要相机相对偏移；由谁控制淡入淡出；提供的会话/暂停/退出回调时机。基础 API 可以先做，镜头级布光作为扩展。
